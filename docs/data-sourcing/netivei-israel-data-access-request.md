## 1. נוסח פנייה מוצע

**נושא: בקשת מידע ובחינת אפשרות לשיתוף נתוני תשתית והגבלות תנועה לרכב כבד**

שלום רב,

אנו מפתחים את TruckSafe Fleet – מערכת לתכנון ולניהול נסיעות של כלי רכב כבדים, שמטרתה לסייע לנהגים ולמנהלי ציי רכב לזהות מראש מגבלות תשתית ותנועה לאורך המסלול, ובהן גובה מעבר מוגבל, מגבלות משקל ומידות, הגבלות לפי שעות, עבודות בדרך וסגירות.

נבקש לברר האם ברשותכם מאגר נתונים רשמי ועדכני, או גורם מקצועי מתאים, שיוכל לסייע בקבלת המידע הבא עבור הכבישים שבאחריותכם:

1. **גשרים, מנהרות, מעברים עיליים ותחתיים:** מזהה נכס קבוע, מיקום וקואורדינטות או גאומטריית GIS, מספר/שם דרך, כיוון נסיעה, נתיב רלוונטי ובעל הנכס/הגורם האחראי.
2. **מגבלות גובה:** גובה פנוי שנמדד בפועל לכל נתיב רלוונטי, גובה המופיע בתמרור, מיקום המדידה המדויק, תאריך המדידה, שיטת המדידה, רמת דיוק/אי-ודאות ואסמכתה רשמית למדידה.
3. **מגבלות רכב כבד נוספות:** משקל כולל, עומס סרן, רוחב, אורך, סוג מטען או מגבלה אחרת, ככל שקיימת.
4. **מגבלות תלויות זמן:** ימים ושעות שבהם ההגבלה חלה, תאריכי תחילה וסיום, חריגים וחגים, והאם מדובר במגבלה קבועה או זמנית.
5. **אירועים ועבודות:** סגירות, צמצומי נתיבים, עבודות תשתית, חסימות והגבלות זמניות, לרבות מועד תחילה/סיום ודרך לקבלת עדכונים דחופים.
6. **עדכון ובקרת נתונים:** תדירות עדכון, מועד האימות האחרון, היסטוריית שינויים, אופן הודעה על ביטול/החלפת רשומה וגורם מקצועי לפניות ותיקונים.

נודה לקבלת מידע גם לגבי:
- זמינות הנתונים בפורמט GIS, ‏CSV, ‏GeoJSON, ‏API או פורמט אחר.
- מילון שדות, מפרט טכני, גבולות הכיסוי ורמת השלמות של המאגר.
- תנאי רישיון, זכויות שימוש, ייחוס מקור, והאם ניתן להשתמש בנתונים כחלק משירות ניווט מסחרי.
- האם קיימים נתונים ארציים או רק נתונים עבור מקטעים/נכסים מסוימים.
- תהליך לקבלת גישה, אישורים נדרשים, עלויות אפשריות והסכם שימוש, ככל שנדרש.

חשוב לנו להבהיר כי לצורכי בטיחות, לא נוכל להתייחס למיקום של גשר בלבד כהוכחה לגובה מעבר או להיעדר מגבלה. נדרש מידע מדוד, רשמי, עדכני וניתן לאימות, כולל כיסוי הנתונים ומועד העדכון.

אם הנושא מטופל ביחידה אחרת, נודה להפניה לגורם המתאים.

## 2. מפרט טכני – שדות מינימום רצויים

| קבוצה | שדות נדרשים |
|---|---|
| זיהוי | source_id, source_version, asset_id, record_status |
| אחריות | road_owner, competent_authority, data_steward |
| מיקום | road_number/name, direction, carriageway, lane, geometry, location_description |
| סוג מגבלה | restriction_type, restriction_value, unit, vehicle_scope |
| גובה | measured_clearance, posted_clearance, measurement_date, method, accuracy, lane_reference, evidence_document |
| תוקף | valid_from, valid_until, days_of_week, time_windows, timezone, permanent_or_temporary |
| עדכניות | published_at, updated_at, last_verified_at, retrieved_at, supersedes_record_id |
| מקור והרשאה | source_url, licence_id, commercial_use_allowed, attribution_required, redistribution_allowed |
| איכות | completeness, confidence, known_gaps, validation_status |

כל שדה חסר צריך להיות מסומן כחסר ולא לקבל ערך משוער. יחידות מדידה ואזור זמן חייבים להיות מפורשים.

## 3. תנאי קבלה לפני שימוש במערכת

אין להכניס נתונים לנתיב החלטה אוטומטי עד שכל התנאים הבאים נבדקו ותועדו:

- **סמכות:** הגוף שסיפק את הרשומה הוא בעל הדרך או גורם מוסמך מטעמו, או שהאסמכתה הרשמית ניתנת לאימות.
- **כיסוי:** ידועים גבולות הכיסוי, הכבישים והנכסים החסרים; אין להציג כיסוי חלקי ככיסוי ארצי.
- **מדידה:** מגבלת גובה מבוססת על מדידה תקפה ומתועדת, ולא על זיהוי גשר, הערכת תמונה או גובה תמרור בלבד.
- **מיקום:** ניתן לשייך את המגבלה לכיוון, למקטע ולנתיב הנכונים ברמת דיוק מתאימה.
- **תוקף:** לכל מגבלה יש תוקף ברור ומנגנון לטיפול ברשומות שפג תוקפן.
- **עדכונים:** קיים תהליך ידוע לקבלת שינויים, ביטולים, עבודות דרך וחסימות זמניות.
- **רישיון:** קיימת הרשאה מפורשת לשימוש המסחרי המתוכנן, לאחסון, לעיבוד ולהצגה באפליקציה.
- **בדיקה עצמאית:** בוצעו בדיקות מדגמיות מול מסמכי מקור ובדיקות שטח/גורם מקצועי לפי הצורך.
- **כשל בטוח:** נתון חסר, ישן, סותר או לא מאומת לא יפורש כהיתר מעבר. המערכת תציג אי-ודאות ותמנע אישור מסלול כאשר אין בסיס בטיחותי מספיק.

## 4. תהליך קליטה מוצע

1. לקבל תחילה דוגמת נתונים ומפרט, ללא חיבור לייצור.
2. לשמור את קובץ המקור, תאריך קבלה, גרסה, רישיון וחתימת/אסמכתת המקור.
3. לטעון לסביבת staging מבודדת בלבד.
4. לבצע בדיקות סכימה, יחידות, גאומטריה, כפילויות, תוקף וסתירות.
5. להעביר כל רשומה לבדיקה אנושית; סטטוס ברירת מחדל הוא `unverified`.
6. לאפשר קידום ל-`verified` רק לאחר עמידה בתנאי הקבלה ותיעוד מאשר.
7. להפעיל ניטור לעדכונים ולרשומות שפג תוקפן.
8. לבצע בדיקות מסלול מקצה לקצה לפני כל החלטה על הפעלה.
